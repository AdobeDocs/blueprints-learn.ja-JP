# デプロイメントの手順

>[!WARNING]
>
>これは、ラボを自分のペースで進めている場合にのみ必要です。 ライブトレーニングコースやイベントを受講している場合は、サンドボックスが既に展開されています。

AJO Architectural Foundations ラボパックは、DEP CLIを使用してサンドボックスにデプロイされます。これは、ラボ全体で使用するスキーマ、データセット、データフロー、サンプルデータを作成するコマンドラインツールで、プロファイルストアと、オーケストレーションされたキャンペーンに使用されるAJO リレーショナルストアの両方をカバーしています。

## 導入するもの

**プロファイルトラック**

- ID名前空間（customerID、planID、productID）
- プロファイルに対して有効な標準XDM フィールドグループ、記述子、スキーマ
- プロファイルに対して有効なカタログデータセット
- ポリシーとオーディエンスの結合
- 3つのサンプルデータセットのプロファイルデータ：Depeche Mode （特性+ イベント）、Stranger Things （特性）、Decisioning （特性）

**リレーショナルトラック**

- customerID ID名前空間
- プライマリキー、外部キー、バージョン記述子を使用した11のリレーショナル XDM スキーマ
- AJOのオーケストレーションされたキャンペーンで11のデータセットを有効
- データランディングゾーンからデータを読み込む11のデータフロー

>[!NOTE]
>
>エンドツーエンドのデプロイメントには、約2時間23分かかります。 プロファイルおよびリレーショナル・トラックは並行して実行され、ほとんどの場合、CLIによって自動的に実行される無人の待機時間です。

## 前提条件

- **ライセンス使用権限。** Real-Time CDP（ストリーミングセグメンテーション付き）およびAdobe Journey Optimizer（オーケストレーションキャンペーン付き）を使用したIMS組織の管理者権限
- **アクセス権。** [Developer Console セットアップ ](developer-console-setup.md)から作成したAPI資格情報を含む、ターゲットサンドボックスに対するすべての権限を持つExperience Platform ロール。
- **Developer Console資格情報。** Adobe Experience Platform APIとAdobe Journey Optimizer APIの両方を含むプロジェクト。 まだ使用していない場合は、まず[Developer Consoleの設定](developer-console-setup.md)に従ってください
- **サンドボックス。** 空です。タイプ `dev`で、デプロイメントを開始する前に少なくとも120分間「準備完了」状態です
- **Node.js.** WindowsまたはMacの最新のLTS バージョン

## &#x200B;1. CLIのインストール

1. [dep-cli リポジトリ ](https://github.com/adobe/dep-cli)を複製またはダウンロードします
1. `dep-cli` ディレクトリから、`npm install`を実行します
1. `npm start`でCLIを開始

>[!NOTE]
>
>上記のコマンドを実行する前に、Node.jsが必要です。 まだNode.jsがインストールされていない場合は、最初にwikiの[Node.js Setup](https://github.com/adobe/dep-cli/wiki/Nodejs-Setup) ページを参照してください。 スクリーンショットや既存のインストールの更新方法など、完全なインストールの詳細については、[ インストール ](https://github.com/adobe/dep-cli/wiki/Installation)wiki ページを参照してください

## &#x200B;2. 環境ファイルの設定

CLIは、環境ファイルが指す任意のサンドボックスにデプロイされるので、何かを実行する前に正しく設定する必要があります。

1. `envFiles/sample-env.json`をコピーして、新しい名前（例：`my-env.json`）を付けます
2. ファイルを開き、[Developer Console setup](developer-console-setup.md)の値を使用して次のフィールドに入力します。

   | **フィールド** | **値** |
   | ---------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
   | `API_KEY` | クライアント ID |
   | `CLIENT_SECRET` | クライアント秘密鍵 |
   | `IMS_ORG` | 組織ID |
   | `SCOPES` | Experience Platform APIとAdobe Journey Optimizer API スコープ <br />*（例：cjm.suppression\_service.client.delete、cjm.suppression\_service.client.all、openid、session、AdobeID、read\_organizations、additional\_info.projectedProductContext）*&#x200B;の両方を含める必要があります |
   | `SANDBOX_NAME` | ターゲットにするサンドボックスは空で、タイプ `dev`である必要があります |

3. ファイルを保存して閉じる

>[!NOTE]
>
>CLI コマンドを実行するたびに、このファイルの名前を求めるプロンプトが表示されるので、以下のすべての手順で再利用できます。

## &#x200B;3. AJO Architectural Foundations メニューの実行

メインメニューから、**AJO arch foundations**&#x200B;を選択します。 6つのステップが2つのトラックに分割されています。

### プロファイルトラック （順次実行）

>[!WARNING]
>
>サンドボックスは、手順1を実行する前に、少なくとも60分間「準備完了」状態である必要があります。

| **手順** | **機能** | **実行する前に** |
| ------------------------ | ------------------------------------------------------------------------------------------- | ---------------------------------- |
| &#x200B;1. プロファイルベースを作成 | ID名前空間、スキーマ、データセット、結合ポリシー、オーディエンスをデプロイします | 60分以上のサンドボックス「準備完了」 |
| &#x200B;2. プロファイルデータの読み込み | データフローを作成し、デペッシュモード、ストレンジャーのもの、および決定プロファイルデータをストリーミングします | 手順1の60分以上待ちます |
| &#x200B;3. プロファイルの正常性を確認 | すべてのプロファイルデータが正しく読み込まれることを検証します | 手順2の後15分以上待ちます |

ステップ 1は約2分、ステップ 2は約6分です。

>[!NOTE]
>
>ステップ 2は、何かが失敗した場合に再実行しても安全です。既存の特性を上書きし、重複したイベントをスキップします。

### リレーショナルトラック

>[!WARNING]
>
>サンドボックスは、手順4または手順6を実行する前に、少なくとも120分間は「準備完了」状態である必要があります。

| **手順** | **機能** | **実行する前に** |
| ----------------------------------- | -------------------------------------------------------------------------------- | ---------------------------------------------------- |
| &#x200B;4. リレーショナルベースの作成 | customerID名前空間とリレーショナルスキーマ/記述子/データセットを作成します | 120分以上のサンドボックス「準備完了」 |
| &#x200B;5. リレーショナルデータの読み込み | 11個のCSV ファイルをアップロードし、それらをロードするデータフローを作成します | ステップ 4の直後に実行：手作業による待ち時間は必要ありません |
| &#x200B;6. リレーショナルベースとデータのデプロイ | 手順4と5を組み合わせて、1回から5分ほど実行します | 120分以上のサンドボックス「準備完了」 |

>[!NOTE]
>
>手順4と5を個別に実行する代わりに、手順6を使用します。伝搬待機を処理すると、1回のパスで同じことを実行します。

>[!NOTE]
>
>上記のすべての待機時間は、CLIによって自動的にチェックされます。 あまりに早い段階で実行すると、ブロックされ、待機する時間が示されます。

## トラブルシューティング

>[!WARNING]
>
>**プロファイルのヘルスチェックが失敗し、イベントが見つかりません。** 一部のプロファイルデータはまだ反映されていません。 さらに15分待って、「プロファイルの正常性を確認」を再実行します。 それでも失敗する場合は、「プロファイルデータを読み込み」を再実行し、15分待って、もう一度確認します。

>[!WARNING]
>
>**リレーショナル データの読み込みが途中で失敗します。** 各API呼び出しは、最大3回再試行されます。 それでも失敗する場合は、クリーンアップによって作成したソース接続、ターゲット接続、データフローが削除され、手順5 （または手順6）をクリーンに再実行できます。 マッピングセットはAPIを介して削除できず、残される可能性があります。これは再デプロイメントには影響しません。

**別の問題が発生しました。** 最後の手段として、CLIのサンドボックス管理メニューからサンドボックスをリセットし、手順1から再デプロイできます。

>[!CAUTION]
>
>サンドボックスのリセットは破壊的です。 CLIでは、続行する前に確認するサンドボックス名を入力するように求められます。
