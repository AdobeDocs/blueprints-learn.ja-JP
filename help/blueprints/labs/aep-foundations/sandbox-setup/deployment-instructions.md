# デプロイメントの手順

>[!NOTE]
>
>これは、ラボを自分のペースで進めている場合にのみ必要です。 ライブトレーニングコースやイベントを受講している場合は、サンドボックスが既に展開されています。

AEP Foundations ラボパックは、ラボ全体で使用するスキーマ、データセット、データフロー、サンプルデータを作成するコマンドラインツールであるDEP CLIを使用して、サンドボックスにデプロイされます。

## 導入するもの

- 4 ID名前空間
- 1つのスキーマクラス、13のフィールドグループ、10のスキーマ
- 12個のID記述子、6個の関係/参照記述子、3個のわかりやすい名前記述子
- 10のカタログデータセット
- 1つのHTTP API ソース接続と10個のデータフロー
- プロファイルデータ：単一のデペッシュモードプロファイル（3つの特性データセット、7つのイベントデータセット）と3つのルックアップデータセット
- 2つのプロファイル結合ポリシーと1つのオーディエンス（任意のイベントストリーミング、1時間以内）

>[!NOTE]
>
>エンドツーエンドのデプロイメントには約2時間24分かかり、そのほとんどはステップ間の無人の待ち時間です。 CLIでは、これらの待機が自動的に適用されるので、自分で何かを実行する必要はありません。

## 前提条件

- **ライセンス使用権限。** Real-Time CDPを使用したIMS組織の管理者権限（ストリーミングセグメンテーション付き）
- **アクセス権。** [Developer Console Setup](developer-console-setup.md)から作成したAPI資格情報を含む、ターゲットサンドボックスに対するすべての権限を持つAdobe Experience Platform ロール。
- **Developer Console資格情報。** Adobe Experience Platform APIを含むプロジェクト。 まだ使用していない場合は、まず[Developer Console Setup](developer-console-setup.md)に従ってください
- **サンドボックス。** 空です。タイプ `dev`で、デプロイメントを開始する前に少なくとも60分間「準備完了」状態です
- **Node.js.** WindowsまたはMacの最新のLTS バージョン

## &#x200B;1. CLIのインストール

1. [dep-cli リポジトリ ](https://github.com/adobe/dep-cli)を複製またはダウンロードします
1. `dep-cli` ディレクトリから、`npm install`を実行します
1. `npm start`でCLIを開始

>[!NOTE]
>
>上記のコマンドを実行する前に、Node.jsが必要です。 まだNode.jsがインストールされていない場合は、最初にwikiの[Node.js Setup](https://github.com/adobe/dep-cli/wiki/Nodejs-Setup) ページを参照してください。 スクリーンショットや既存のインストールの更新方法など、完全なインストールの詳細については、[ インストール ](https://github.com/adobe/dep-cli/wiki/Installation)wiki ページを参照してください

## &#x200B;2. 環境ファイルの設定

CLIは、環境ファイルが指す任意のサンドボックスにデプロイされるので、何かを実行する前に正しく設定する必要があります。

1. `envFiles/sample-env.json`をコピーして、新しい名前（例：`my-env.json`）を付けます
1. ファイルを開き、[Developer Console Setup](developer-console-setup.md)の値を使用して次のフィールドに入力します。

   | **フィールド** | **値** |
   | --------------- | ------------------------------------------------------------------------------------------------------------------------------------- |
   | `API_KEY` | クライアント ID |
   | `CLIENT_SECRET` | クライアント秘密鍵 |
   | `IMS_ORG` | 組織ID |
   | `SCOPES` | Experience Platform API スコープ（openid、session、AdobeID、read_organizations、additional_info.projectedProductContext）を含める必要があります |
   | `SANDBOX_NAME` | ターゲットにするサンドボックスは空で、タイプ `dev`である必要があります |

1. ファイルを保存して閉じる

>[!NOTE]
>
>CLI コマンドを実行するたびに、このファイルの名前を求めるプロンプトが表示されるので、以下のすべての手順で再利用できます。

## &#x200B;3. AEPの基礎メニューの実行

メインメニューから、**AEP foundations**&#x200B;を選択します。 3つのステップがあり、それらを順番に実行する必要があります。

>[!WARNING]
>
>サンドボックスは、手順1を実行する前に、少なくとも60分間「準備完了」状態である必要があります。

| **手順** | **機能** | **実行する前に** |
| ----------------------- | ------------------------------------------------------------------------------------------ | ------------------------------- |
| &#x200B;1. プロファイルベースを作成 | ID名前空間、スキーマ、データセット、結合ポリシー、オーディエンスをデプロイします | 60分以上のサンドボックス「準備完了」 |
| &#x200B;2. プロファイルデータの読み込み | データフローを作成し、プロファイルとルックアップデータをストリーミングします | 手順1の60分以上待ちます |
| &#x200B;3. プロファイルの正常性を確認 | すべてのデータが正しく読み込まれたことを検証します | 手順2の後15分以上待ちます |

ステップ 1は実行に約2分かかり、ステップ 2は約6分、ステップ 3は独自の待ち時間のない迅速な検証です。 ステップ間の60分と15分のギャップは、AEPが2時間のタイムラインの大部分を占める、舞台裏でのデータ伝播を完了させるための時間です。

>[!NOTE]
>
>CLIは、これらの待機時間を自動的にチェックします。 ステップを早く実行しすぎると、ブロックされ、残り時間が示されます。自分で時計を追跡する必要はありません。

>[!NOTE]
>
>ステップ 2は、何か問題が発生した場合に再実行しても安全です。 既存の特性レコードを上書きし、重複するイベントをスキップします。

## トラブルシューティング

>[!WARNING]
>
>**ヘルスチェックが失敗し、イベントが見つかりません**。 一部のプロファイルデータはまだ反映されていません。 さらに15分待って、「プロファイルの正常性を確認」を再実行します。 それでも失敗する場合は、「プロファイルデータを読み込み」を再実行し、15分待って、もう一度確認します。

**別の問題が発生しました。** 最後の手段として、CLIのサンドボックス管理メニューからサンドボックスをリセットし、手順1から再デプロイできます。

>[!CAUTION]
>
>サンドボックスのリセットは破壊的です。 CLIでは、続行する前に確認するサンドボックス名を入力するように求められます。
